# The extension (`app/`)

A Manifest V3 Chrome extension: React 19, TypeScript strict, Tailwind 3, Vite 6 with `@crxjs/vite-plugin`. CI uses Node 22 and pnpm 10; `app/pnpm-workspace.yaml` carries the build-script allowlist for pnpm 10, so keep `app/pnpm-lock.yaml` readable by that major.

## Layout

- `manifest.json`: MV3. Permissions `tabs`, `sidePanel`, `storage`, `scripting`, `alarms`; host permission `<all_urls>` (a decided trade-off, `docs/launch-checklist.md` Phase 0). `description` is the store summary (132 characters max, read-only in the dashboard; changing it needs a release). `key` pins the local extension ID `lgkgkmjldppeidgafolhfpepmabnnbhe` and is stripped from the store zip by CI; never remove it. `version` is stamped by release-please.
- `src/background/service-worker.ts`, `src/content/index.ts`, `src/sidepanel/` (the main UI with `pages/`), `src/options/` (settings, license and account, BYO key, model picker), `src/components/` (`ui/`, `paywall/`), `src/styles/`, `src/types/seo.ts`, `src/test/` (Vitest setup, entitlement fixtures).
- `src/lib/`: `seo-analyzer.ts` and `scoring.ts` (local, free, never gated); `ai.ts` (routing facade) with `anthropic.ts` (BYO key, direct) and `ai-proxy.ts` (hosted `/ai/generate`); `entitlement-keys.ts` (public JWKs per environment and `BACKEND_BASE_URL`), `entitlement.ts` (verification), `entitlement-store.ts` (the flags every gate reads); `backend.ts` (`/license/*`), `billing.ts` and `checkout-store.ts` (`/billing/*`), `plans.ts` (live Stripe price ids); `storage.ts`, `store.ts` (Zustand); `docs-links.ts` (per-check Learn More URLs into `site/docs/`).
- `e2e/`: Playwright with `--load-extension` (headed Chromium only, built `dist/` first): `extension.e2e.ts`, `freemium.e2e.ts`, `manifest-v3.e2e.ts` (the pre-submission checks against the built manifest), shared `fixtures.ts`.
- `dev.html` with `vite.config.dev.ts`: the browser harness (`pnpm -C app dev`), which proxies `/api/anthropic` and `/api/backend` (staging) to sidestep CORS. The extension build (`vite.config.ts`) never uses those paths.

## Standards

- TypeScript strict, no `any`; function components and hooks only; a props interface per component; `cn()` from `src/lib/utils.ts` for conditional classes; Tailwind tokens from `tailwind.config.ts`, no hardcoded colors. 2-space indentation.
- Every Free versus Pro gate reads a flag from `entitlement-store.ts` (`canUseAdvancedOptions`, `canUseMultiLanguage`, `canUseSchema`, `canBringOwnKey`, `useCanUseAI()`, `useAiStatus()` with modes `byok`, `pro`, `free`, `locked`), never an ad hoc API-key or raw-license check. Scoring and the score breakdown are never gated. The quota the UI shows is a cache of what the server reported. `docs/free-vs-pro-gating.md` is the matrix.
- Pro is a signed claim: the extension bundles public Ed25519 JWKs only and verifies issuer `optia-backend`, audience `optia-extension`, algorithm, expiry and `kid`. Anything that fails resolves to free. Nothing in this repo may mint, sign or hold a secret. `docs/architecture.md` is the reference.
- Hosted AI sends the keyword and the relevant page snippets only; BYO-key requests go straight to Anthropic. A changed data flow updates `site/privacy.html`, `docs/privacy-policy.md` and `docs/chrome-web-store-data-disclosure.md` in the same PR.
- `docs-links.ts` slugs must exist under `site/docs/` (generated by `scripts/build-docs-site.mjs`); `seo-analyzer.test.ts` fails otherwise.
- Tests beside the code as `*.test.ts(x)`, Vitest in jsdom with Testing Library; new behaviour gets a test, a fixed bug gets a regression test. Before reporting: `pnpm -C app lint`, `pnpm -C app tsc --noEmit`, `pnpm -C app test`, `pnpm -C app build`; `pnpm -C app test:e2e` when the manifest, the service worker, the content script or the freemium flow changed.
- Never hand-edit the version in `manifest.json` or `package.json`; release-please stamps both plus the root `package.json`.
