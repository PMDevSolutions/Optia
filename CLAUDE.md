## What this repo is

Optia is a Chrome extension (Manifest V3) that scores any page for a target keyword and offers AI title, meta description, heading and alt-text suggestions powered by Claude. It is open-core freemium: this public repo ships the extension, the GitHub Pages site and the docs; the private `PMDevSolutions/optia-backend` (a Cloudflare Worker at `https://api.optia-api.com`, staging `https://optia-backend-staging.paul-130.workers.dev`) holds Stripe billing, Ed25519 license signing and the metered AI proxy. Pro is $5/month or $50/year; free users get 25 AI recommendations a month, Pro 1,000, or unlimited with their own Anthropic key. SEO analysis runs entirely in the browser; there is no analytics or tracking. Built and maintained by Paul Mulligan (PMDS). Live on the Chrome Web Store as `gnlidlpidaoalbbmekofjednjkhhmehn`; the manifest `key` pins local unpacked loads to `lgkgkmjldppeidgafolhfpepmabnnbhe`.

## Commands

Extension work runs from `app/` (pnpm 10 and Node 22 in CI):

```
pnpm -C app install --frozen-lockfile
pnpm -C app dev            browser harness at http://localhost:5173, backend calls proxied to staging
pnpm -C app dev:ext        extension build in watch mode; load app/dist unpacked
pnpm -C app lint
pnpm -C app tsc --noEmit
pnpm -C app test           Vitest in jsdom
pnpm -C app build          tsc, then vite build into app/dist
pnpm -C app test:e2e       Playwright against the built extension (build first; headed Chromium)
node scripts/claude-code-conformance.js --root . --strict
node --test scripts/__tests__/*.test.js
```

The root `package.json` exists for release-please's version stamp and has no scripts.

## Deploys and releases

- A push to `main` that touches `site/**` deploys the site to GitHub Pages (`pages.yml`). Every push to `main` runs release-please, which maintains one Release PR. **Merging the Release PR is the human release gate**: it stamps the version into `package.json`, `app/package.json` and `app/manifest.json`, updates `CHANGELOG.md`, tags `vX.Y.Z`, publishes a GitHub Release and attaches `optia-X.Y.Z.zip` with the manifest `key` stripped. Paul uploads that zip in the Chrome Web Store Developer Dashboard under paul@pmds.info; the store needs a version greater than the published one. `docs/RELEASING.md` has the detail. Never hand-edit a version.
- CI (`ci.yml`) on every PR and push to `main`: lint, typecheck, test, build, the MV3 e2e under xvfb, and Claude Code conformance with the hook tests. Branch protection on `main` requires those checks (`docs/RELEASING.md`, Branch protection).
- The `release-guard` hook asks before `git push`, `gh pr merge`, `gh release create|edit|upload|delete`, `gh workflow run` and `gh run rerun`, and denies them inside subagents. Do not look for a way around it; hand Paul the command.

## Working conventions

- Work on a branch, open a PR, let CI pass; Paul merges. Squash-merge with a Conventional Commit title (`type(scope): summary`), one concern per PR; release-please reads those titles.
- Never add paid or secret server logic to this repo. The client verifies entitlements with public keys only and the server meters everything scarce (`docs/architecture.md`). Never gate SEO scoring; gates read flags from `app/src/lib/entitlement-store.ts`.
- `site/privacy.html` and `docs/privacy-policy.md` stay in sync, and the store disclosure matches the real data flows. Published URLs (site pages, docs slugs) are referenced by the store listing, Stripe and the extension, so keep them stable.
- Marketing runs from the Maecenas repo against `brand-guidelines.json`; this repo holds the lockfile and the store assets only. Product voice: plainspoken, honest, practical; never hypey, corporate or smug.
- The coding agent edits `.claude/settings.json` (tracked), never `.claude/settings.local.json` (gitignored, personal).
- Tooling on Paul's Mac: `node` 24, `pnpm` 12, `jq`, `gh` (PAMulligan). CI pins pnpm 10; keep both lockfiles readable by it.
